# Security policy

GuardSpec is intentionally small and local-first, but parser, path-resolution, Action and MCP issues may still affect users. Please report suspected vulnerabilities privately rather than through a public issue.

## Reporting

Open a confidential GitHub Security Advisory for this repository if available, or contact the repository owner through GitHub with the subject **“GuardSpec security report”**. Include a minimal reproducer, affected version or commit, expected/actual behavior, and a safe remediation suggestion where possible.

Do **not** include API keys, personal data, private repository source, production logs, or a live exploit against a third party. A synthetic fixture is preferred.

## Scope

Reports are in scope when they concern path escape, unintended command/network execution, unsafe policy parsing, unintentional data exposure through MCP/Action output, dependency compromise, or an incorrectly documented security guarantee. Differences between an Agent host’s behavior and the policy guidance generated by GuardSpec are also useful reports, but GuardSpec cannot guarantee enforcement by external agents.

## Response

Maintainers will acknowledge a good-faith report, assess reproducibility and impact, coordinate a fix where justified, and publish a release note when disclosure is appropriate. No response-time SLA or bounty is offered.
